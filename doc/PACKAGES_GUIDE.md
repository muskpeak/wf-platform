# 核心基础 Packages 使用指南

这 7 个基础包是我们整个 Monorepo 架构的“底层基石”。它们的作用是将那些**与具体业务无关，但每个应用、每个模块都会用到的通用能力**抽象并沉淀下来。

这样以后无论是开发主站 `apps/web`，还是新开一个后台管理系统 `apps/admin`，都能直接像搭积木一样复用这些能力，而不需要把相同的逻辑复制粘贴一遍。

以下是它们的具体作用和后续的使用规范：

---

## 1. `@wf-platform/dev-tools` (开发辅助工具)
- **作用**：专门用来存放开发阶段的“黑科技”。比如 API 数据 Mock（使用 MSW）、本地调试面板、性能监控脚本等。
- **怎么用**：当后端接口没写好时，前端不用干等。你可以在 `packages/dev-tools/src/mocks/handlers.ts` 里拦截请求并返回假数据。前端依然正常发起 `fetch('/api/user')`，但会被这个拦截器在浏览器层面上拦截，从而实现前后端完全并行开发。生产环境打包时，这些代码会自动剔除，不会影响线上包体积。

## 2. `@wf-platform/feature-flags` (功能开关系统)
- **作用**：大型项目必备的“特性开关”或“灰度发布”管理引擎。
- **怎么用**：如果你们想上一个新功能（比如上线新的 Lottery 玩法），但又不想马上对所有用户公开，或者怕有重大 Bug。你就可以在这个包里定义一个配置表（比如 `isLotteryV2Enabled`）。主页通过判断这个开关来决定要不要渲染新按钮。一旦线上出了致命 Bug，运维或后台可以直接把开关关掉，前端瞬间回滚，完全不需要重新部署前端代码。

## 3. `@wf-platform/navigation` (导航注册与路由系统)
- **作用**：统一管理整个平台的路由地址映射、侧边栏菜单和面包屑导航。
- **怎么用**：由于你的各个业务模块（比如 `lottery`）是动态接入大底座的，主站的导航菜单不应该写死在 `apps/web` 里。这个包提供了一套“注册表”机制。`lottery` 模块只需往这个包里登记 `registerRoute({ path: '/lottery', name: '彩票业务' })`，主站的顶部导航栏就能自动获取并渲染出对应按钮。

## 4. `@wf-platform/permissions` (权限管理系统)
- **作用**：统一处理整个前端角色的权限控制逻辑。
- **怎么用**：提供例如 `<RequireAuth role="VIP">` 这样的包装组件，或者 `checkPermission(user, 'WITHDRAW_FUNDS')` 的校验方法。所有涉及到 VIP 判定、黑名单拦截、地区限制（IP 阻断）、或者管理员后台权限判定的代码，全收敛在这里，保证安全逻辑不泄露到普通的 UI 组件里。

## 5. `@wf-platform/contracts` (通用合约体系)
- **作用**：独立存放所有公用的智能合约配置（如 ERC20, ERC721 规范）的 ABI、部署好的合约地址常量、以及由 wagmi CLI 自动生成的强类型 Hook 文件。
- **怎么用**：当你在任何业务模块需要查询余额或者授权 USDC 时，直接 `import { USDC_ABI } from '@wf-platform/contracts'`。这样如果以后合约升级，只需在这个包里改一次，整个平台的项目都会随之生效。

## 6. `@wf-platform/testing` (测试工具与夹具)
- **作用**：提供给自动化测试框架（如 Jest, Cypress, Playwright）使用的公共 Utilities 和假数据生成器。
- **怎么用**：当你写单元测试时，常常需要用一堆 Provider（比如 Web3Provider, ThemeProvider）把组件包起来。这个包会提供一个统一的 `renderWithProviders(Component)` 方法，并且包含各种用于测试的“假以太坊账户”生成函数。专门为保障代码质量服务，严格做到测试代码不污染业务代码。

## 7. `@wf-platform/analytics` (统一埋点追踪层)
- **作用**：大厂必备的网关级模块，收拢所有的用户行为追踪（Google Analytics, Mixpanel, Sentry 错误上报等）。
- **怎么用**：业务代码里绝对不要直接写死 `ga('send', 'event')` 这种第三方平台的 API。而是调用这个包暴露的规范化接口：`trackEvent('BUTTON_CLICK', { btnName: 'Deposit' })`。这个包在底层决定把这条数据发送给哪个具体的数据分析平台。未来就算你们换了数据分析服务商，业务代码也一行都不需要改。
